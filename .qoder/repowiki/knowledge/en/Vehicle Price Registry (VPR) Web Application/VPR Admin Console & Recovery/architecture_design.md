Three flat PHP entry scripts, each `require_once`'ing the shared core library `db.php` and rendering self-contained HTML pages — no framework or controller layer.

- `admin2000.php` is the main dashboard: unauthenticated POSTs trigger a login flow that checks `login_attempts` against `VPR_MAX_LOGIN_ATTEMPTS` / `VPR_LOGIN_BLOCK_SECONDS`, calls `verify_admin_password`, sets `$_SESSION['vpr_admin']`, and uses `audit_admin` for every state change. Once authenticated it dispatches on `$_POST['action']` (`save_pricing`, `add_interest`, `clear_interest`) and renders stats panels (searches day/week/month, active interests with priority rank, recent Paynow transactions, system health).
- `recover_admin.php` implements a two-step password recovery: request mode generates a one-time token via `create_recovery_token()` and emails a reset link; reset mode validates the token with `verify_recovery_token()`, enforces a minimum 12-character password, persists it via `set_admin_password()`, clears `login_attempts`, and marks the token used.
- `repair_payment_db.php` is an admin-only utility that runs the V12.9 schema migration through `db()`, then uses `PRAGMA table_info(payments)` to verify all required columns exist, reporting missing fields.

Dependency direction is strictly inward: these scripts depend on `db.php` for DB access, security helpers (`security_headers`, `secure_session_start`, `csrf_token`, `verify_csrf`, `admin_session_valid`), audit logging, and admin credential functions; nothing in this module is imported by other application pages except via navigation links.
