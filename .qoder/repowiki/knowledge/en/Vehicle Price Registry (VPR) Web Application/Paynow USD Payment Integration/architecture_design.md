Flat page-style module with four sibling scripts, each a single-purpose HTTP endpoint sharing one `db.php` core:
- `paynow_create.php`: POST-only JSON API. Validates registration/vehicle fields, inserts a `payments` row (status `Created`), calls `paynow_http_post` to initialise the transaction on Paynow, validates the gateway response hash, stores the returned `browserurl`/`pollurl`, and returns them as JSON.
- `paynow_result.php`: Paynow webhook receiver. Verifies the signed hash and reference via `hash_equals`, polls the stored `pollurl` through `paynow_poll_status`, reconciles amount/status, persists the result, and triggers `finalize_vpr_search_from_payment` when paid.
- `paynow_return.php`: Thin HTML+JS landing page rendered by the browser after Paynow redirects back; it calls `paynow_status.php` via fetch and either closes itself or forwards the user to the certificate URL.
- `paynow_status.php`: GET JSON polling endpoint used by the return page. Checks `return_token` against the persisted token, optionally re-polls Paynow if not yet paid, updates the row, and returns `{ok,status,paid,certificate_url,message}`.

Dependency direction is one-way: these scripts depend on helpers in `db.php` (`paynow_*`, `vpr_price`, `security_headers`, `finalize_vpr_search_from_payment`) but expose no shared library — every script is independently deployable. State lives in a SQLite `payments` table with columns `merchant_reference`, `amount`, `currency`, `status`, `return_token`, `pollurl`, `paynow_reference`, `paid_at`, `last_error`, plus foreign links to `searches` via `search_id`.
