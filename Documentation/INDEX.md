# VPR — Vehicle Pledge Registry · Repository Index

Generated 2026-10-17 from a full source read of application version 14.2 (`VPR_VERSION` in config.php).

## What this is

A single-purpose PHP 8 + SQLite web application for low-cost Apache shared hosting. No framework, no Composer, no build step, no third-party libraries (XLSX and PDF files are generated by hand-rolled writers). The public pays a per-search fee — USD via a server-verified Paynow integration, or ZiG via a static payment link — to check whether an active interest is recorded against a vehicle (Zimbabwean `AAA1111` registration format). The result is a printable A4 certificate. Admins record and clear interests, manage live pricing, view analytics, and export/import Excel backups.

## Architecture at a glance

- Flat, page-per-function layout. Every entry script requires `db.php`, which is both the shared library and the schema bootstrap (it creates/migrates all tables on first use via `ensure_v6_schema`).
- Storage: one SQLite file, `data/vpr.sqlite` (WAL journal mode, 5 s busy timeout).
- Configuration: constants in `config.php` (gitignored; contains secrets). Live prices come from the DB `settings` table, not the config constants.
- HTTPS is enforced twice — in `.htaccess` (301 rewrite) and in PHP (`security_headers()`).

Public search request flow:

```
index.php
 ├─ price = 0.00 (free)  → POST search_process.php → certificate.php?id&token
 └─ USD path             → AJAX paynow_create.php → Paynow popup
                           ├─ poll paynow_status.php (every 2 s)
                           └─ Paynow signed callback → paynow_result.php
                               └─ finalize_vpr_search_from_payment() → certificate.php?id&token
 └─ ZiG path             → static Paynow link popup (no auto certificate release)
```

## Data model

Ten tables (created/migrated by `ensure_v6_schema`; several also created lazily on first use):

- `vehicles` — registration number is unique (dupes consolidated at startup); brand/model/chassis enriched with the best value seen.
- `interests` — `status` ACTIVE/CLEARED; chronological `created_at` defines "Order of VPR Registration", ranks never renumber when earlier interests clear.
- `searches` — every check ever run; stores the result string, HMAC-hashed IP, certificate number and access token.
- `search_interests` — immutable per-certificate snapshot of active interests at search time.
- `payments` — one row per Paynow attempt; `status`, `pollurl`, `return_token`, `last_error`, `search_id` link to the released search.
- `settings` — live pricing (`price_USD`, `price_ZIG`) and other key/value settings.
- `login_attempts` — IP-hash based throttling (5 attempts / 15 min block).
- `admin_audit` — admin action log with hashed IPs.
- `admin_recovery` — SHA-256-hashed one-time recovery tokens.
- `system_metadata` — `schema_version` (currently 12; independent of app version 14.2).

Note: the bundled `data/vpr.sqlite` predates V12.9 — it still has a leftover `finalizing` column and lacks the `settings`/admin tables. The first request self-heals it via `ensure_v6_schema`; document the intended schema above, not the stale bundled file.

## Key flows

1. **Free search (price 0.00)** — `index.php` JS submits directly to `search_process.php`; Paynow is never mentioned or invoked.
2. **USD paid search** — `paynow_create.php` creates a server-side transaction (SHA-512 hash over fields + integration key) → popup opens Paynow → `paynow_status.php` polls every 2 s while Paynow posts the signed result to `paynow_result.php` → hash, reference and exact amount are verified → `finalize_vpr_search_from_payment()` atomically claims the payment (re-check inside the transaction prevents duplicate searches from callback/poll races) → certificate URL is released.
3. **ZiG search** — opens the static Paynow link popup (`VPR_ZIG_PAYNOW_LINK`); popup closure is explicitly not accepted as payment proof, so no automatic certificate release. `zig_api_charge.php` stays disabled (`VPR_ZIG_API_ENABLED=false`) until a real provider API exists.
4. **Admin** — password login with IP-hash rate limiting, security alert emails (≥3 failures), audit log; live price changes take effect immediately; a 0.00 price makes searches free.
5. **Backup / restore** — `data_exchange.php?action=export` writes a 5-sheet XLSX (`Metadata`, `Vehicles`, `Interests`, `Searches`, `SearchInterests`); `?action=import` merges by registration number / certificate number (schema versions 1–12 accepted, 25 MB cap).

## Security model

- HTTPS forced (`.htaccess` 301 + PHP), HSTS, CSP (`form-action 'self' https://www.paynow.co.zw`), frame-ancestors none, nosniff, no-referrer, restrictive Permissions-Policy.
- Admin sessions: strict mode, httponly, SameSite=Strict, 48-char session IDs, 30-min idle timeout, CSRF token on every admin POST, `session_regenerate_id` on login.
- Certificates gated by 48-hex access tokens compared with `hash_equals` (or admin session).
- Paynow: every response hash-validated; polled reference must equal the merchant reference; amount must equal the configured USD fee; only paid states (`paid`, `awaiting delivery`, `delivered`) release results.
- Server: `data/`, `config.php`, `db.php`, SQLite/backup/log/secret file patterns blocked; only GET/POST/HEAD allowed; 25 MB request cap; directory listings off.
- Admin password storage overrides config once rotated: `data/admin_auth.json` holds a bcrypt hash.
